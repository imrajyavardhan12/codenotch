# Codenotch

macOS menu-bar agent that shows AI-tool usage limits (Claude Code, Codex, Cursor, …) in a notch-style panel on the
screen edge. Swift, SwiftUI over an AppKit `NSPanel`, Xcode project generated by XcodeGen. Read `ARCHITECTURE.md`
before touching providers, `UsageStore` or the notch layout.

## Commands

- `make test`: regenerate the project and run the unit tests via `xcodebuild` (~15 s incremental)
- `make build` / `make run`: Debug build; `run` relaunches the app
- With plain `swift`/`xcodebuild`, export `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` (the Makefile
  sets it)
- Logs: `/usr/bin/log show --last 10m --predicate 'subsystem == "io.github.imrajyavardhan12.codenotch"' --info --debug`

## Verify before you say done

- Every change: `make test`. Quote `** TEST SUCCEEDED **`, or the failing test names.
- Bug fix: first add the test that fails without the fix. `Tests/` mirrors `Sources/` by concern, not by file.
- Provider changes: response shapes are pinned by recorded payloads in `Tests/*UsageTests.swift`. Add the payload
  you saw as a fixture.
- Layout math (`Sources/Notch/NotchLayout.swift`): check against `docs/design/frame-124-hover-tooltip.png`; every
  constant is quoted from that frame through `Design.px(_:)`.
- Performance claims: numbers from a Release build, idle and with the panel open, before and after:
  `top -pid $(pgrep -x Codenotch) -l 4 -s 10 -stats pid,cpu,idlew,power` and `sample $(pgrep -x Codenotch) 10`.

## Rules

- Providers declare a `Fidelity` and degrade every failure to a `ProviderStatus`. Never invent a number.
- Keychain credentials go through `CredentialCache`, not a read on every poll.
- Debug builds are ad-hoc signed, so keychain "Always Allow" grants don't survive a rebuild. That prompt is
  expected; one on an already-granted build is a bug.
- `make release` (Developer ID, notarization, Sparkle feed) is the maintainer's job.
- Comments explain why, not what. No premature abstraction.
